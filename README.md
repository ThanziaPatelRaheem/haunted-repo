## What if deleted code could speak?

Most developers delete a file and move on.

**Git remembers. Haunted Repo gives it a voice.**

Haunted Repo is a local AI-powered developer tool that uncovers deleted files from Git history, recovers their code, and uses **Gemma 3 4B running locally through Ollama** to generate ghost stories and technical investigations.

And if the ghost has something to say, you can let it read its story aloud.

---

## Overview

Every Git repository has a history. Some files survive for years, while others disappear after a refactor, a bug fix, or a developer deciding, "We don't need this anymore."

But deleting a file doesn't necessarily erase its past.

Haunted Repo uses Git history to uncover deleted files and recover their available contents. Instead of simply displaying old code, it combines real Git evidence with locally generated AI storytelling and technical analysis.

Each recovered file gets two opportunities to speak:

- **The Ghost's Story:** A fictional account of its former life, generated by Gemma 3.
- **The Reaper's Verdict:** A technical investigation of the recovered code, including its likely purpose and potential issues.

And if reading a ghost story isn't spooky enough, you can let the ghost read it aloud.

Because apparently, even deleted code has unfinished business.

## Features

### Repository Scanner

Enter the absolute path of a local Git repository to begin the investigation.

- Validate and scan local Git repositories.
- Identify deleted files from Git history.
- Display discovered files in an interactive graveyard.
- Select individual files to explore their past.

### Graveyard of Deleted Files

Not every deleted file rests in peace.

The graveyard displays files discovered through Git history and lets users investigate what remains of their code.

### Git History and Code Recovery

Before asking AI to interpret anything, Haunted Repo retrieves available historical evidence using Git.

- Recover deleted file contents.
- Inspect historical source code.
- Explore available Git information associated with the file.

The Git data provides the evidence. The AI provides the interpretation.

### The Ghost's Story — Powered by Gemma 3

Every deleted file has a story. Some were replaced. Some became obsolete. Others may have simply outlived their usefulness.

Using **Gemma 3 4B**, Haunted Repo generates fictional ghost stories inspired by recovered code and available Git history.

The model runs locally through Ollama, allowing the storytelling experience to work without sending source code to a hosted AI provider.

### Hear My Last Words — Ghost Narration

Why read a ghost story when the ghost can tell it itself?

The **Hear My Last Words** feature uses the browser's Web Speech API to narrate AI-generated stories aloud.

The application also includes atmospheric sound effects to complement the storytelling experience.

Narration is handled by the browser, while Gemma generates the story itself.

### The Reaper's Verdict — Technical Investigation

After the storytelling comes the technical interrogation.

Using Gemma 3, Haunted Repo generates an analysis of the recovered source code, exploring its likely purpose, implementation, and potential technical weaknesses.

Unlike the fictional ghost story, this feature focuses on technical interpretation.

The verdict is AI-generated and should be reviewed against the actual code and Git evidence.

### Haunted Interface

The frontend combines a responsive layout with atmospheric visuals, animations, and sound effects.

The goal is to make exploring Git history feel less like reading a log and more like investigating a forgotten piece of software.

## How It Works

### 1. Scan the Repository

The user provides the absolute filesystem path to a local Git repository.

The Express backend validates the repository and uses Git commands to discover deleted files in its history.

### 2. Explore the Graveyard

Deleted files are displayed in the frontend.

The user selects a file to investigate its available history and recovered contents.

### 3. Recover the Code

The backend retrieves historical source code and available Git evidence.

This information forms the context for AI generation.

### 4. Generate with Gemma 3

Haunted Repo uses two task-specific prompts.

**Ghost Story Prompt**

Instructs Gemma 3 to transform the recovered file's history and code into a fictional narrative from the perspective of forgotten software.

**Technical Investigation Prompt**

Instructs Gemma 3 to analyze the recovered code and provide a technical interpretation of its purpose and potential issues.

Both prompts are processed through Ollama's local API using the `gemma3:4b` model.

### 5. Narrate the Story

The browser's speech synthesis functionality reads the generated ghost story aloud.

Atmospheric audio effects complement the experience.

## Why Gemma 3?

Gemma 3 is central to Haunted Repo, rather than an optional addition.

Git can tell us which files were deleted and recover available historical content. However, Git doesn't explain the story behind that code or provide a natural-language interpretation of its implementation.

Gemma 3 bridges that gap by powering two distinct experiences:

- **Creative storytelling:** Transforming recovered code and historical context into fictional ghost stories.
- **Technical reasoning:** Interpreting the purpose, structure, and potential weaknesses of recovered code.

The same local model supports both creative and technical tasks through different prompts.

### Why Run Gemma Locally?

Haunted Repo uses **Gemma 3 4B with Ollama**, allowing inference to run on the developer's machine.

**Privacy**

Recovered source code can be processed locally without being sent to a hosted AI inference service.

**No Per-Request API Charges**

AI generation uses local computing resources rather than a paid hosted model API.

**Offline Inference**

Once Ollama and the model are installed, AI generation can run without an internet connection.

**Developer Control**

Prompts and model configurations can be modified, and alternative compatible local models can be explored.

**Open Innovation**

Using an open-weight model makes it possible to build and experiment with AI-powered developer tools while retaining control over the inference environment.

## Getting Started

### Prerequisites

Install the following:

- Node.js and npm
- Git
- Ollama
- Gemma 3 4B model

Haunted Repo runs locally. The backend must have filesystem access to the repositories being scanned.

### 1. Clone the Repository

```bash
git clone YOUR_GITHUB_REPOSITORY_URL
cd haunted-repo
```

Replace `YOUR_GITHUB_REPOSITORY_URL` with the actual GitHub repository URL.

### 2. Install Ollama and Gemma 3

Download Ollama from [ollama.com](https://ollama.com).

Pull the model:

```bash
ollama pull gemma3:4b
```

Ensure Ollama is running before starting the application.

### 3. Configure the Backend

Open a terminal in the project directory:

```bash
cd server
npm install
```

Create a `.env` file inside `server/`:

```env
PORT=3000
OLLAMA_URL=http://localhost:11434
OLLAMA_MODEL=gemma3:4b
```

Start the backend:

```bash
npm run dev
```

The backend runs at `http://localhost:3000`.

### 4. Start the Frontend

Open another terminal from the project root:

```bash
cd client
npm install
npm run dev
```

Open the development URL displayed by Vite, normally:

`http://localhost:5173`

### 5. Scan a Local Repository

Enter the absolute path to a Git repository stored on your machine.

For example:

```text
/path/to/your/local/git-repository
```

For testing, use a repository containing files that were previously committed and subsequently deleted.

Select a recovered file to explore its code, generate a ghost story, or request a technical investigation.

## Technical Considerations

### Git Evidence vs. AI Interpretation

Git history provides the factual evidence about deleted files.

Gemma generates fictional stories and technical interpretations using the available context.

The generated content does not establish why a file was actually deleted, and technical conclusions should be checked against the source code.

### Local Repository Access

The application scans repositories accessible to the backend's local filesystem.

It does not currently support remote GitHub repository scanning or cloud-based repository uploads.

### AI Performance

Generation speed depends on the local machine, model size, prompt length, and available computing resources.

### Browser Narration

Speech synthesis voices and playback behavior vary by browser and operating system.

---

## Limitations

- Requires a local Git repository with accessible history.
- Historical recovery depends on the Git data still available.
- AI-generated technical explanations may contain inaccuracies.
- Local inference requires sufficient hardware resources.
- Narration depends on browser speech synthesis support.
- Only repositories the user is authorized to access should be scanned.
